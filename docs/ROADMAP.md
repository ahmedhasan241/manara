# Roadmap

The full feature list is large, so it ships in phases. Each phase is usable on its own.

## Phase 1 — Foundation (this commit)

- [x] Monorepo layout, architecture doc
- [x] Laravel API: tenants, users, memberships, RBAC, Sanctum auth, TOTP MFA
- [x] Courses, enrollments, assessments, grades, class sessions, attendance, materials
- [x] Announcements and in-app notifications
- [x] Offline sync endpoints (pull/push, idempotent by UUID)
- [x] CSV exports for grades and attendance
- [x] Plans and subscriptions, platform admin endpoints
- [x] Encrypted columns for sensitive data, activity log
- [x] Four Next.js apps with shared UI, dark mode, API client
- [x] Portal: role-aware dashboard, gradebook, roll call with offline queue, materials,
      announcements, notifications, analytics, settings (MFA, devices, data export), en/ar + RTL
- [x] Flutter app: login, MFA, courses, grades, offline roll call, biometric unlock
      (written without a local Flutter SDK; run `flutter analyze` before relying on it)
- [x] CI workflow (not yet run on GitHub)

Known gaps in phase 1:
- Teachers can manage every course in their workspace, not just their own.
- Plan limits (max students/staff, storage) are stored but not enforced.
- Members page exists in the API but not yet in the portal UI.

## Phase 2 — Communication (done)

- [x] Laravel Reverb real-time channels (`users.{id}`), token-based channel auth
- [x] E2E encrypted messaging: direct and group conversations, contact rules by role,
      web client with libsodium (X25519 + XChaCha20-Poly1305)
- [x] Encrypted key backup (Argon2id passphrase), multi-device history sync,
      encrypted backup download
- [x] Push notifications via FCM HTTP v1, per-conversation mute, live in-app toasts,
      failed-job alerts for platform staff
- [x] Mobile: push token registration and in-app alerts
- [x] Mobile: encrypted chat (passphrase setup/unlock, conversations, groups, mute),
      key kept in the platform keystore, live over Reverb with 30-second polling as
      backup, tapping a message notification opens the conversation. Format is shared
      with the web client and checked by `mobile/test/e2e_compat_test.dart` against a
      fixture generated by the web code.

Known gaps in phase 2:
- The unlocked private key is kept in the browser's localStorage for convenience; a
  non-extractable WebCrypto wrapping key in IndexedDB would be stronger.
- No forward secrecy (see ARCHITECTURE.md).
- Attachments in messages are not supported yet.

## Phase 2.5 — Online lessons and new design (done)

- [x] Live lessons on Zoom (Server-to-Server OAuth, webhooks) or Jitsi, behind one
      `VideoProvider` interface so more providers can be added
- [x] Full cycle: schedule → notify (in-app, email) → reminder 15 min before (push)
      → host starts → "Live now" banner and push → students join (tracked) → end →
      attendance taken automatically → recording downloaded from Zoom (or uploaded /
      linked) → students notified → watch on the course page with view counts
- [x] Recordings stream through short-lived signed URLs (seekable), hide/show, delete
- [x] "Nebula" design system: new sidebar (collapsible, animated, grouped), split-screen
      login with animated showcase, animated tabs, stat count-ups, staggered lists,
      skeleton loading, page transitions, new fonts (Plus Jakarta Sans + IBM Plex Sans
      Arabic); respects reduced-motion; applied to the portal and platform admin
- [x] Mobile: live and upcoming lessons with Join, course lessons and recordings

Known gaps:
- Lesson times are shown in the viewer's time zone on the web, but emails use UTC.
- Zoom participant events aren't used; "joined" means opened the link from Manara.
- No in-app video player on mobile yet (recordings open in the in-app browser).
- Marketing site and school sites use the new tokens and fonts but not the new layouts.

## Phase 2.6 — Separate products per audience (done)

- [x] Staff portal for teachers, lecturers/doctors, school and university admins
- [x] Learner & family portal (new app): progress overview with weighted averages,
      attendance, grade trends and alerts; courses, live lessons, recordings, materials,
      announcements, encrypted messages; parents switch between several children
- [x] Guardianships: a parent can follow several children (replaces one-child link)
- [x] Role routing between the two portals; shared code in `@educloud/portal-kit`
- [x] Product website: audiences, features, packages with monthly/yearly toggle and a
      comparison table, testimonials, FAQ — all text editable from the admin
- [x] Platform admin: user directory across all workspaces (filter by role, suspend
      with immediate sign-out, reset two-factor), subscriber detail (people by role,
      change package, history), subscriptions (trials ending, extend, activate, cancel),
      package editor, website editor

Known gaps:
- Learner portal has no two-factor setup or language switch yet (staff portal does).
- Stripe billing isn't connected; "Activate" marks manual payments.
- Website edits appear on the public site within a minute (cache), not instantly.

## Phase 2.7 — Design system, 3D and global UI (done)

- [x] Six colour palettes × light/dark, switchable live; palette-aware logo, charts and 3D
- [x] Effects kit: tilt cards, spotlight, magnetic buttons, rotating words, marquee,
      scroll progress, gradient borders, confetti; reduced-motion and touch aware
- [x] 3D "knowledge crystal" on the website hero and every login page
- [x] New shell header: breadcrumb, ⌘K command palette, language, appearance,
      notifications and account menus; phone bottom tab bar
- [x] Six interface languages with RTL; browser language detected on first visit
- [x] Website: 3D hero, rotating audiences, marquee, tilt + spotlight feature cards,
      mobile menu sheet, appearance menu
- [x] Learner portal: celebration (confetti) for grades of 90%+
- [x] Admin "Design system" page showing every token and component
- [x] Fixed: stale/mismatched sessions now go to sign-in instead of an error page

Known gaps:
- Page bodies (forms, tables, empty states) are still mostly English; the shell, nav,
  command palette and key greetings are translated. Marketing content is English.
- Palette choice is saved per device (localStorage), not per account.

## Phase 2.8 — "Campus" design and learning features (done)

- [x] Campus palette (teal on sky, navy headings, Poppins), now the default in every app;
      the other six palettes stay selectable
- [x] Light sidebar with pastel icon tiles, teal page banners, course covers generated per
      course, category pills and tiles, continue-learning carousels, pastel lesson list
- [x] Course categories; lesson progress ("Lesson 5 of 7") on courses and the learner overview
- [x] Ratings and reviews: enrolled students rate courses (1–5 stars + comment), breakdown on
      the course page, staff "Reviews" page across all courses
- [x] Calendar (both portals): live lessons, due dates and deadlines by month with a day agenda
- [x] New sign-in screen with step pill, new staff/learner/admin home pages
- [x] Lesson room in the "Meeting" layout: stage with host and participants, floating
      control bar (join / start / end), course contents and attendance on the side
- [x] Checked at 375px: no sideways scrolling on the new pages

Known gaps:
- Marketing site keeps its own header/footer; only tokens and fonts changed there.

## Phase 2.9 — Course marketplace and public learning website (done)

- [x] Any teacher, lecturer/doctor, school or university turns a course into an online
      course: landing page (subtitle, outcomes, requirements, level, language), price,
      curriculum of sections and lectures (uploaded video, video link incl. YouTube/Vimeo,
      or article), free preview lectures, reordering, publish/unpublish
- [x] The learner portal is now the public website: home, course catalog with search,
      categories, level/price filters and sorting, course pages, institutions, instructor
      profiles; browsing needs no account
- [x] Sign-in / sign-up dialog (also two-factor and "forgot password"); buying, checkout,
      watching and My learning ask to sign in first and return to where you were
- [x] Cart, checkout and orders; free courses enroll instantly; purchase history
- [x] Course player: resume where you left off, progress per lecture, mark complete,
      ratings and reviews from owners
- [x] Schools and universities add people one by one or paste a whole class, and can
      enroll them in a course at the same time (they also get the online course)
- [x] Password set/reset by email link (also how invited people set their first password)
- [x] Staff "Online sales" page (revenue, earnings after platform fee, learners per course);
      admin "Course marketplace" page (sales, orders, pause/restore courses)
- [x] Illustrated characters (teachers, doctors, students, graduates, readers) in several
      skin tones and hair styles, used across the website and dashboards

Known gaps:
- Payments run in **test mode** (`PAYMENTS_DRIVER=test`, refused in production): no money
  moves and card details never leave the browser. Stripe Checkout is the next step.
- Instructor payouts are reported, not paid out.
- No quizzes inside lectures, or coupons yet.
- Lecture uploads go through a server action (limit 512 MB); very large files should use
  direct-to-storage uploads.

## Phase 2.10 — Languages, local currencies and a less generic look (done)

- [x] Every screen in all five web apps is translated into Arabic, English, French,
      Spanish, Portuguese and Chinese (1,177 messages, with proper plural forms; Arabic
      uses all six). Arabic is the default and lays out right-to-left. The type check fails
      if any language misses a message
- [x] API messages, validation errors, emails and notifications follow the visitor's
      language (`X-Locale`, else `Accept-Language`); each user's last language is saved so
      queued notifications use it
- [x] Prices show in the visitor's currency: picked from their country (host geo header,
      else browser time zone, else language region), changeable next to the language
      picker. Rates come from `GET /api/v1/currencies`, refreshed hourly by
      `currencies:refresh`, with saved fallback rates. Charges stay in the course
      currency; checkout says what will actually be charged and orders record the rate
- [x] Design pass: Arabic headline font (Alexandria), handwritten notes (Caveat / Aref
      Ruqaa), hand-drawn underlines, arrows and stars instead of gradient text and blurred
      glows, tactile "pressed" buttons, no negative letter-spacing in Arabic
- [x] Wishlist: heart on course pages, `/wishlist`, header shortcut; courses you get leave it
- [x] Certificates of completion, issued automatically when every lecture is done, with a
      printable page that doubles as public verification (`/certificate/EC-XXXX-XXXX`) and
      a Certificates tab in My learning

- [x] One calm look everywhere: a single teal palette (palettes removed), light/dark/system
      only, IBM Plex Sans + Plex Sans Arabic + Plex Mono, a compact type scale, and ~12%
      tighter spacing on phones
- [x] Components on Radix (shadcn/ui style, in `@educloud/ui`): dialogs, sheets, dropdown
      menus, popovers, tabs, toggle groups, accordion, select, switch, checkbox, tooltips,
      toasts (sonner) and a confirm dialog replacing browser `confirm()`
- [x] Website text and plans are translated in the API: website sections are edited per
      language (the admin edits the language they're viewing), plans have per-language
      name/description/features in the plan editor
- [x] SEO: favicons, Apple icon and social cards for every app; canonical + hreflang
      (`?lang=xx` opens any page in that language); sitemaps and robots (portals and admin
      are noindex); schema.org Course, Organization, SoftwareApplication and FAQPage

- [x] Discount codes: staff create percent-off codes (one course or all, use limit, end
      date) under "Discount codes"; learners apply them in the cart; orders keep the code,
      the discount and each course's list price, and sales count what was actually paid
- [x] Lecture notes: private, time-stamped notes in the player's Notes tab; clicking a
      note's time jumps to that moment (switching lecture if needed)
- [x] Learning streak and weekly goal on My learning: days in a row, minutes this week
      against a goal the learner picks, and a day-by-day strip (time comes from the
      player's progress pings; seeks don't count)
- [x] Each course link shares its own card (title, teacher, category; Arabic titles render
      with IBM Plex Sans Arabic)

- [x] Motion and scrolling: smooth (inertial) scrolling on desktop via Lenis, headers that
      slide away on scroll-down, a back-to-top button with a reading-progress ring, page
      transitions in every app, lists and cards that reveal as they scroll into view,
      CSS scroll-timeline reveals and layered hero parallax, hover lift on cards. All of it
      switches off for people who prefer reduced motion; touch devices keep native scroll

Known gaps:
- Course content written by teachers stays in the language it was written in (no
  per-course translations yet).
- Learning time is only tracked for files and links played in the page's own player;
  YouTube/Vimeo embeds report completion but not minutes.
- Live rates need outbound HTTPS from the API server; until the first refresh it uses
  the fallback rates in `config/currencies.php`.
